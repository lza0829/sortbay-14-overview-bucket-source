# 分拣过机台（Sortbay）

骨架：过机扫描装载 → 口门路由裁决 → 错分回流批次 → 封袋班次对账

- 前端 http://127.0.0.1:6600
- API http://127.0.0.1:11600

## 调度屏四格真源

调度屏「待路由 / 已路由 / 错分回流 / 已封袋」四格**只以事件流滚动汇总为准**：

- 真源：`sort_events` 只追加事件流（装载 / 裁决 / 回流 / 开袋 / 入袋 / 封袋）。
- 四格、口门在口、袋册封态均由事件流**重放投影**得到，可由选定班次 + 事件区间重放复算。
- `scans.status` 等只是事件流的物化缓存，写口在同一事务内重算；缓存与重放不一致会被
  `/api/调度屏/对账` 报为「状态/口门/袋拧花」。
- 口门在口、袋册封态是同一真源的旁证投影，**绝不反向用其可变数字纠偏四格**。
- **手工改计一律拒绝**（`POST /api/调度屏/手工改计` 返回 409）：四格不接受任何非事件写入，
  不得伪装成写口成功。纠偏请走对应写口或补记事件并经审计。
- 审计由事件写入统一产出，与事件流同事务落库，`/api/调度屏/对账` 会列出审计缺口。
- 所有写口使用 `BEGIN IMMEDIATE` 单事务，装载与封袋并发不会漂数；任一步失败整笔回滚，
  不留半截回执。

### 相关接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/调度屏` | 四格 + 口门在口 + 袋册（重放投影） |
| `GET /api/调度屏/重放` | 由事件流重放复算四格；`截止事件编号` 可重放到某一前缀 |
| `GET /api/调度屏/轨迹` | 逐事件落格轨迹，含袋级封袋逐件归因 |
| `GET /api/调度屏/对账` | 重放 vs 扫描册/口门/袋册/审计的差异与对齐结论 |
| `POST /api/调度屏/手工改计` | 一律拒绝（409） |

老库在启动时由 `app.seed.backfill_events()` 按现有扫描册/袋册状态补记事件并重算缓存，
补记按 开袋 → 装载/裁决/入袋 → 封袋 的生命周期顺序、仅在缺事件时补，幂等。
